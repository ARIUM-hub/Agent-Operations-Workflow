# 最近记录筛选与搜索设计

## 背景

客户使用问题归因智能体已经支持单条分析、批量分析、人工反馈复核和 CSV 导出。随着最近记录列表中结果增多，运营或数据分析专员需要更快定位某个平台、某类问题、某个责任方或某种复核状态的记录。

本轮目标是在不增加后端复杂度的前提下，为当前工作台增加轻量的前端本地筛选和搜索能力。

## 已确认范围

- 在“最近记录”区域增加筛选栏。
- 支持关键词搜索，匹配平台、报告文本和记录 ID。
- 支持按问题类型筛选。
- 支持按优先责任方筛选。
- 支持按反馈状态筛选。
- 反馈状态包含：全部、未复核、已认可、已修正。
- 筛选只作用于页面当前展示的最近 10 条记录。
- JavaScript 不可用时，最近记录仍按原样展示。
- CSV 导出仍导出全部记录，不受页面筛选影响。

## 非目标

- 不新增后端查询接口。
- 不做全库分页搜索。
- 不做跨 JSONL 全量前端加载。
- 不改变 JSONL 存储结构。
- 不改变 CSV 导出语义。
- 不引入前端框架或构建工具。

## 推荐方案

采用“前端本地渐进增强”方案。

后端模板在每条最近记录上输出用于筛选的 `data-*` 属性，包括平台、问题类型、责任方、反馈状态和可搜索文本。前端 JavaScript 读取这些属性，在用户输入关键词或切换下拉条件时，对当前 DOM 中的记录进行显示/隐藏。

这个方案开发成本低、风险小，不影响现有 API 和存储。它的限制是只能筛选页面当前最近 10 条记录，但这符合本轮 MVP 范围。

## 页面结构

在“最近记录”标题和记录列表之间新增筛选栏：

- 关键词输入框：占位提示“搜索平台、报告或记录 ID”。
- 问题类型下拉：默认“全部问题类型”。
- 责任方下拉：默认“全部责任方”。
- 反馈状态下拉：默认“全部复核状态”。
- 清空按钮：一键恢复全部条件。
- 匹配数量提示：显示“当前显示 X / Y 条”。

筛选栏使用普通 HTML 表单控件，不需要提交。控件要有可见标签或 `aria-label`。

## 数据属性

每条最近记录输出以下属性：

```html
<article
  class="record"
  data-record-id="..."
  data-platform="..."
  data-issue-category="..."
  data-responsibility="..."
  data-feedback-status="unreviewed|accepted|corrected"
  data-search-text="..."
>
```

`data-search-text` 包含平台、报告文本、记录 ID 和反馈备注。为避免 HTML 注入风险，模板继续依赖 Jinja 自动转义。

## 前端行为

JavaScript 新增本地筛选逻辑：

1. 页面加载时绑定筛选控件。
2. 输入关键词或切换下拉框时立即筛选。
3. 搜索使用大小写不敏感匹配。
4. 下拉条件使用精确匹配。
5. 多个条件之间使用 AND 关系。
6. 没有匹配记录时显示“没有符合条件的记录”。
7. 点击“清空”恢复默认条件并显示全部当前记录。

## 错误处理与降级

- 如果页面没有最近记录，筛选栏仍可显示，但匹配数量为 `0 / 0`。
- 如果某条历史记录缺少某个字段，对应数据属性为空。
- JavaScript 加载失败时，所有记录仍然可见。
- 筛选不会发起网络请求，也不会修改记录或反馈。

## 测试策略

自动测试覆盖：

- 首页包含最近记录筛选栏。
- 首页记录卡片包含筛选所需的 `data-*` 属性。
- 静态 JS 包含筛选绑定、筛选执行和清空逻辑函数。
- 静态 CSS 包含筛选栏和空结果提示样式。

手动验收覆盖：

- 有多条最近记录时，关键词搜索可以隐藏不匹配记录。
- 按问题类型、责任方和反馈状态筛选时，显示数量随之更新。
- 多个条件组合时只显示同时满足的记录。
- 点击清空后恢复显示全部当前记录。
- CSV 导出仍下载全部记录，不受筛选条件影响。

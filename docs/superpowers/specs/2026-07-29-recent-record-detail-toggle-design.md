# 最近记录详情展开设计

## 背景

客户使用问题归因智能体已经支持单条和批量分析、人工复核、最近记录筛选、运营概览、筛选 CSV 导出和时间范围筛选。当前“最近记录”区域只展示平台、问题类型、责任方、证据强度、反馈状态和完整报告摘要。

运营或分析专员在复核最近记录时，经常需要快速看到结构化明细，例如客户问题、业务原因、下一步建议、待补充信息和人工备注。现在如果不导出 CSV，就只能阅读报告文本，定位细节不够快。

本轮目标是在不新增接口、不改变存储的前提下，为最近记录卡片增加轻量详情展开能力。

## 目标

- 每条最近记录增加“查看详情/收起详情”按钮。
- 详情区域默认隐藏，展开后展示结构化分析字段。
- 详情字段包含客户问题、问题类型、业务原因、优先责任方、证据强度、下一步建议、需要补充信息、人工复核状态和备注。
- 按钮支持 `aria-expanded` 和 `aria-controls`，方便键盘和辅助技术使用。
- 新提交的单条或批量分析记录也能带详情结构和展开按钮。
- 不改变 JSONL 存储、分析 API、反馈 API、筛选 API 或 CSV 导出语义。

## 非目标

- 不做单条记录详情 API。
- 不做弹窗或抽屉。
- 不做详情编辑。
- 不做分页或跨全库加载。
- 不做富文本渲染。
- 不调用模型，不增加供应商请求。

## 推荐方案

在服务端模板中，为每条最近记录输出一个详情区域。区域使用现有 `record.analysis` 和 `record.feedback` 数据，默认加 `hidden`。每张卡片增加一个按钮，按钮通过 `aria-controls` 指向对应详情区域，并用 `aria-expanded="false"` 表示初始折叠。

前端新增一个小型 `bindRecordDetails()`，页面加载时绑定所有 `[data-record-detail-toggle]` 按钮。点击后切换详情区域的 `hidden` 状态、按钮的 `aria-expanded` 和按钮文案。新分析结果通过 `prependRecentRecord()` 插入最近记录时，也生成同样结构，并重新绑定或直接绑定该卡片按钮。

这个方案保持渐进增强：如果 JavaScript 不可用，用户仍能看到现有摘要；如果 JavaScript 可用，则能按需展开结构化详情。

## 备选方案

方案 A：新增 `/api/records/{id}` 详情接口，点击后异步加载。这样可以减少初始 HTML，但会增加 API、错误处理和网络请求。当前最近记录只有 10 条，直接模板输出更简单，因此不采用。

方案 B：使用 `<details><summary>` 原生元素。可访问性和无 JS 降级很好，但现有项目已经有按钮式交互和 JS 钩子测试模式；为了保持交互文案和样式一致，本轮采用按钮加隐藏区域。

方案 C：把详情做成弹窗。视觉聚焦更强，但会引入焦点管理、遮罩、关闭逻辑和移动端适配，不适合当前小步迭代。

## 详情内容

详情区域按卡片网格展示：

- 客户问题：`analysis.attribution.customer_problem`
- 问题类型：`analysis.attribution.issue_category`
- 业务原因：`analysis.attribution.root_causes`
- 优先责任方：`analysis.attribution.primary_responsibility`
- 证据强度：`analysis.attribution.evidence_strength`
- 下一步建议：`analysis.attribution.recommended_actions`
- 需要补充信息：`analysis.attribution.missing_information`
- 人工复核：未复核、已认可或已修正
- 人工备注：`feedback.note`

枚举值可以先沿用当前记录元信息里的原始值；前端动态插入的新卡片继续使用现有 `labelFor()` 显示中文标签。

## 前端行为

页面加载时：

1. 绑定所有详情按钮。
2. 所有详情区域保持隐藏。
3. 按钮文案为“查看详情”。

点击按钮时：

1. 找到 `aria-controls` 对应的详情区域。
2. 如果详情隐藏，则显示详情、设置 `aria-expanded="true"`、按钮文案改为“收起详情”。
3. 如果详情已显示，则隐藏详情、设置 `aria-expanded="false"`、按钮文案改为“查看详情”。

最近记录筛选隐藏整张记录卡片时，不需要改变详情展开状态。用户清空筛选后，卡片可以保持之前的展开或收起状态。

## 错误处理

- 缺少详情区域：点击按钮时直接跳过，不抛异常。
- 字段为空：显示“暂无信息”。
- 列表字段为空：显示“暂无信息”。
- 反馈为空：显示“未复核”。

## 测试策略

- 首页 HTML 测试覆盖详情按钮、详情区域、`aria-expanded`、`aria-controls` 和关键字段文案。
- 静态 JS 测试覆盖 `bindRecordDetails`、`toggleRecordDetail` 和 `data-record-detail-toggle` 钩子。
- 静态 CSS 测试覆盖详情区域样式类。
- 回归测试确认最近记录筛选钩子仍存在。
- 全量测试确认现有分析、反馈、导出和概览功能不受影响。

## 验收标准

- 最近记录每张卡片有“查看详情”按钮。
- 点击按钮可以展开和收起结构化详情。
- 展开详情包含分析字段和人工反馈字段。
- 新分析插入到最近记录列表后也有详情展开能力。
- 不新增后端接口，不改变现有 API 响应。
- 全量测试通过。

## 后续可扩展

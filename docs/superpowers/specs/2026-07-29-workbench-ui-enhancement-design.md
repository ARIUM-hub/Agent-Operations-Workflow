# 轻量工作台前端增强设计

## 背景

客户使用问题归因智能体的 MVP 已具备单条会话分析 API、文件解析、规则归因、中文报告生成和 JSONL 存档能力。当前页面仍偏基础：用户提交后更像在调用 API，缺少页面内结果展示、上传文件入口和可扫读的最近记录。

本轮增强目标是把现有单页升级成真正可用的轻量分析工作台，让运营专员或数据分析专员可以在一个页面内完成输入、分析、查看结果和复查最近记录。

## 已确认范围

- 方案选择：轻量工作台增强。
- 页面范围：继续使用单页工作台，不新增多页面后台。
- 输入方式：支持粘贴客服会话和上传客服会话文件。
- 输出方式：分析结果直接显示在页面中，不要求用户阅读 JSON。
- 技术方式：使用原生 HTML、CSS、JavaScript 渐进增强，不引入 React、Vue 或构建工具。
- 后端接口：继续复用 `/api/analyze` 和 `/api/analyze-file`。
- 适用用户：运营专员和数据分析专员。

## 非目标

- 不做多页面管理后台。
- 不做登录、权限、团队协作。
- 不做批量分析和汇总报表。
- 不做人工修正闭环。
- 不新增模型供应商调用。
- 不重构现有归因引擎。
- 不引入前端框架或复杂前端构建链。

## 用户流程

用户打开首页后，默认看到粘贴会话输入区。用户可以选择平台来源，粘贴客服对话，然后点击分析。页面显示加载状态，分析完成后在页面内展示结构化结果卡片，同时最近记录列表刷新或提示用户本次结果已保存。

如果用户切换到上传文件输入区，可以选择 `txt`、`log`、`csv`、`xlsx` 或 `xlsm` 文件。提交成功后，页面同样显示分析结果。文件为空、格式不支持或后端解析失败时，错误信息显示在上传表单附近。

普通 HTML 表单需要保留可用性。JavaScript 增强失败时，用户仍能通过表单提交到后端接口并得到响应；JavaScript 正常工作时，提交过程为无刷新体验。

## 页面结构

### 顶部区域

顶部保留产品名称、业务场景说明和本地规则模式状态。视觉风格保持运营工具气质：信息清晰、控件稳定、颜色克制，不做营销页式大首屏。

### 输入区域

输入区域使用两个标签页：

- `粘贴会话`：平台来源输入框、客服会话文本框、分析按钮。
- `上传文件`：平台来源输入框、文件选择控件、支持格式提示、分析按钮。

两个标签页共享结果展示区，但各自拥有独立错误提示位置。按钮需要有加载状态，提交期间避免重复点击。

### 结果区域

分析结果拆成五块固定区域：

- 客户问题。
- 业务原因。
- 优先责任方。
- 下一步建议。
- 需要补充。

每块结果优先从结构化字段中生成，必要时回退到完整报告文本。结果区域需要展示平台来源、问题类型、证据强度和记录 ID，方便用户复核。

### 最近记录区域

最近记录改成摘要列表。每条记录显示：

- 平台来源。
- 问题类型。
- 优先责任方。
- 证据强度。
- 报告摘要。

最近记录仍使用现有 JSONL 存档，不新增数据库。首版展示最近 10 条即可。

## 前端行为

页面使用一份静态 JavaScript 文件处理渐进增强：

1. 绑定两个输入标签页的切换。
2. 拦截粘贴分析表单提交，调用 `/api/analyze`。
3. 拦截文件上传表单提交，调用 `/api/analyze-file`。
4. 提交时显示加载状态并禁用对应按钮。
5. 成功时渲染结果区域。
6. 失败时在对应表单附近显示中文错误。
7. 分析成功后把本次结果插入最近记录列表顶部。

错误信息要说明原因和恢复动作。例如“客服会话不能为空，请粘贴至少一轮客户反馈”或“文件类型不支持，请上传 txt、log、csv、xlsx 或 xlsm 文件”。

## 后端配合

现有 API 已返回 `record_id` 和 `analysis`。为了前端更稳定，结果渲染应优先读取：

- `analysis.report`
- `analysis.request.platform`
- `analysis.attribution.issue_category`
- `analysis.attribution.primary_responsibility`
- `analysis.attribution.evidence_strength`
- `analysis.attribution.customer_problem`
- `analysis.attribution.root_causes`
- `analysis.attribution.recommended_actions`
- `analysis.attribution.missing_information`

如果前端需要中文标签，优先由后端返回枚举值对应的字段，或由前端用固定映射表转换。首版可以在前端维护小型映射表，避免扩大后端 API。

## 可访问性与响应式

- 表单字段必须有可见标签。
- 标签页按钮需要表达当前选中状态。
- 错误提示使用 `role="alert"` 或等价语义。
- 输入控件、按钮和文件控件在移动端保持足够高度。
- 结果卡片在桌面端可以双列排布，在移动端改为单列。
- 键盘用户可以完成标签页切换、输入、上传和提交。
- 焦点状态必须可见。

## 验证方式

自动测试覆盖：

- 首页包含两个输入标签页。
- 首页包含粘贴表单和上传表单。
- 首页引用前端 JavaScript 文件。
- 调用 `/api/analyze` 后返回结构化字段可供前端渲染。
- 调用 `/api/analyze-file` 上传文本文件后返回分析结果。

手动验收覆盖：

- 粘贴 README 样例后，页面内显示客户问题、业务原因、优先责任方、下一步建议和需要补充。
- 上传包含同样样例的 `txt` 文件后，页面内显示同类结果。
- 空文本提交显示中文错误。
- 不支持的文件类型显示中文错误。
- 最近记录中出现新分析摘要。

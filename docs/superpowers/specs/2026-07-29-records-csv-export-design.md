# 分析记录 CSV 导出设计

## 背景

客户使用问题归因智能体已经支持单条分析、批量上传分析、JSONL 存档和人工反馈复核。运营或数据分析专员完成批量分析和复核后，通常需要把结果带到 Excel、飞书表格或其他 BI/复盘流程里继续处理。

本轮目标是增加一个轻量、稳定、低风险的 CSV 导出能力，让用户可以导出当前本地 JSONL 中的全部分析记录和人工反馈字段。

## 已确认范围

- 新增 CSV 导出接口：`GET /api/records/export.csv`。
- 导出当前 JSONL 中所有分析记录，包含已合并的最新人工反馈。
- CSV 使用 UTF-8 with BOM，优先保证 Windows Excel 直接打开中文不乱码。
- 页面“最近记录”标题区域新增“导出 CSV”按钮。
- 导出字段覆盖运营复盘需要的核心信息。
- 不调用模型供应商，不做批量模型请求，不做后台任务。

## 非目标

- 不做 Excel `.xlsx` 样式化导出。
- 不做筛选导出。
- 不做分页导出。
- 不做异步导出任务。
- 不做权限控制或登录。
- 不把 JSONL 存储迁移到数据库。

## 导出字段

CSV 首行固定为中文表头，便于运营直接阅读：

- 记录 ID
- 创建时间
- 平台
- 客户问题
- 问题类型
- 业务原因
- 优先责任方
- 证据强度
- 下一步建议
- 需要补充
- 是否认可
- 修正问题类型
- 修正责任方
- 人工备注

字段来源：

- 分析字段来自 `record["analysis"]`。
- 反馈字段来自 `record["feedback"]`。
- 枚举字段首版导出当前 API 保存的枚举值，保持机器可处理性；中文报告字段用于人工阅读。
- 列表字段用中文顿号或分号连接，避免单元格里出现复杂 JSON。

## 后端设计

新增一个小型导出模块或 helper，负责把 `AnalysisStore.list_records()` 的结果转换为 CSV 文本。FastAPI 端点只负责读取记录、生成响应和设置下载头。

接口：

```text
GET /api/records/export.csv
```

响应：

- `Content-Type: text/csv; charset=utf-8`
- `Content-Disposition: attachment; filename=customer-issue-records.csv`
- 响应体以 UTF-8 BOM 开头。

当没有记录时，仍导出只有表头的 CSV。这样用户点击导出不会报错，也能看到系统支持哪些字段。

## 前端设计

在“最近记录”标题区域添加一个链接按钮：

```html
<a class="secondary-action" href="/api/records/export.csv">导出 CSV</a>
```

这保持渐进增强：即使 JavaScript 不可用，用户也可以下载 CSV。当前不做前端筛选，也不需要额外 JS。

## 错误处理

- JSONL 文件不存在：导出空表头 CSV。
- 单条历史记录缺少某些字段：该字段留空，不影响其它记录导出。
- 反馈为空：反馈相关字段留空。
- 字段中包含换行、逗号或引号：使用 Python `csv` 模块正确转义。

## 测试策略

自动测试覆盖：

- 导出接口返回 `200`。
- 响应体以 UTF-8 BOM 开头。
- CSV 表头包含“记录 ID”“客户问题”“人工备注”等关键列。
- 已保存反馈的记录导出时包含反馈备注和修正责任方。
- 没有记录时导出只有表头的 CSV。
- 首页包含“导出 CSV”入口。

回归验证：

- 全量 `python -m pytest -q` 通过。
- 现有单条分析、文件上传、批量分析和反馈 API 不受影响。

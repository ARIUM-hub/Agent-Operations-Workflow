# 批量分析与人工复核闭环设计

## 背景

客户使用问题归因智能体已经具备单条会话分析、文件上传、中文报告、JSONL 存档和轻量工作台。下一步需要把它从“单条分析工具”推进到“可复核的小型作业流”：运营或数据分析专员可以一次处理多条海外电商客服会话，并对系统判断进行认可、修正和备注。

本轮仍保持本地、低复杂度、低风险实现。系统不接入模型供应商，不做后台队列，不做并发压力分析，也不引入数据库和登录权限。

## 已确认范围

- 继续服务海外电商客服会话分析场景，平台不限于 Amazon、TikTok Shop，也支持其他海外电商平台。
- 支持批量上传一个文件，解析出多条客服会话并逐条生成分析结果。
- 支持对每条分析记录保存人工反馈，包括认可状态、修正问题类型、修正责任方和备注。
- 继续使用 JSONL 作为本地存储，不迁移到数据库。
- 继续使用单页工作台，不新增多页面后台。
- 保持普通表单和 API 可测试，不引入前端构建工具。

## 非目标

- 不做平台 API 同步。
- 不做批处理任务队列和进度轮询。
- 不做多用户权限、登录或团队协作。
- 不做模型调用、模型重试或供应商健康检查。
- 不做大规模并发批量分析。
- 不做复杂报表、趋势图和 SKU 维度聚合。
- 不修改或删除历史 JSONL 记录，而是通过追加式存储保留审计痕迹。

## 推荐方案

采用“轻量批量复核”方案。

后端新增一个批量文件分析接口，文件解析后按会话边界拆分为多条文本，逐条复用现有 `_run_analysis` 流程，得到多条独立记录。前端新增“批量上传”标签页，提交后直接显示批量结果列表。每条结果卡片提供人工反馈表单，用户可以标记认可或不认可，并可填写修正字段和备注。

反馈保存采用追加式 JSONL 事件。原始分析记录不被覆盖；当用户提交反馈时，存储层追加一条 `feedback` 事件，并在读取记录时把最新反馈合并到对应分析记录。这样实现简单，也避免误改历史分析结果。

## 数据拆分规则

批量文件首版使用显式分隔符拆分会话，避免误把同一会话拆散。

支持的分隔符：

- 空行加 `---` 加空行。
- 空行加 `===` 加空行。
- CSV 或 Excel 中每一行作为一条会话，当存在 `conversation`、`conversation_text`、`message`、`内容` 等字段时优先读取对应字段。

如果文件只解析出一条会话，仍允许返回一条批量结果。单次批量默认最多处理 50 条，超过时返回 422，提示用户拆分文件。这个限制用于避免本地界面卡顿，也为未来模型接入保留安全边界。

## 后端接口

### 批量文件分析

新增 `POST /api/analyze-batch-file`。

输入：

- `platform`: 平台来源，默认 `Other overseas platform`。
- `file`: 批量客服会话文件，支持 `txt`、`log`、`csv`、`xlsx`、`xlsm`。

输出：

- `batch_id`: 本次批量分析 ID。
- `count`: 成功分析条数。
- `records`: 每条记录包含 `record_id` 和 `analysis`，结构沿用单条分析接口。

错误：

- 空文件返回 422。
- 不支持文件类型返回 422。
- 超过 50 条会话返回 422。
- 单条会话为空时跳过空片段；全部为空时返回 422。

### 人工反馈保存

新增 `POST /api/records/{record_id}/feedback`。

输入：

- `accepted`: 布尔值，表示是否认可系统分析。
- `corrected_issue_category`: 可选，修正后的问题类型枚举值。
- `corrected_responsibility`: 可选，修正后的责任方枚举值。
- `note`: 可选，人工备注。

输出：

- `record_id`
- `feedback`

如果记录不存在，返回 404。反馈字段需要裁剪空白；空字符串按未填写处理。

## 存储设计

现有分析记录保持如下结构：

```json
{"id":"...","created_at":"...","analysis":{...},"feedback":null}
```

新增反馈事件结构：

```json
{"type":"feedback","record_id":"...","updated_at":"...","feedback":{...}}
```

`AnalysisStore.list_records()` 读取 JSONL 时同时处理分析记录和反馈事件：先收集分析记录，再把每个 `record_id` 的最新反馈合并到对应记录。这样旧数据仍可读取，新反馈也能显示在页面上。

## 前端工作台

页面新增第三个标签页：`批量上传`。

批量上传表单包含：

- 平台来源。
- 文件选择控件。
- 分隔符和最多 50 条提示。
- 上传并批量分析按钮。
- 中文错误提示区域。

批量结果展示：

- 显示本次批量 ID 和成功条数。
- 每条结果以卡片呈现客户问题、业务原因、责任方、证据强度和记录 ID。
- 每条卡片下方提供反馈区：认可/不认可、修正问题类型、修正责任方、备注和保存按钮。
- 保存成功后在卡片上显示“已保存反馈”状态。

最近记录列表也显示反馈状态。已认可显示“已认可”，不认可或有修正显示“已修正”。

## 错误处理

- 批量上传文件为空：提示“文件中没有可分析会话，请检查导出内容”。
- 批量条数过多：提示“单次最多分析 50 条，请拆分文件后重试”。
- 反馈记录不存在：提示“记录不存在或已被清理，请刷新页面后重试”。
- 前端提交失败：保留用户已填写的反馈内容，不清空表单。

## 测试策略

后端测试：

- 批量文本文件按分隔符拆成多条会话。
- 批量 CSV 文件按行生成多条会话。
- 超过 50 条会话返回 422。
- 批量分析接口返回多条记录，并保存到 JSONL。
- 反馈接口可以保存认可状态和修正字段。
- 反馈接口对不存在记录返回 404。
- `list_records()` 能把最新反馈合并到分析记录。

前端测试：

- 首页包含批量上传标签页和表单。
- 首页包含反馈表单元素和脚本钩子。
- 静态 JS 包含批量提交和反馈提交函数。

回归验证：

- 现有单条粘贴分析仍可用。
- 现有单文件上传分析仍可用。
- 全量 `python -m pytest -q` 通过。

## 后续扩展

- 批量任务队列和进度展示。
- 批量分析结果导出 CSV 或 Excel。
- 按平台、问题类型、责任方做汇总报表。
- 将人工反馈用于优化规则和未来提示词。
- 接入商品资料包辅助归因。

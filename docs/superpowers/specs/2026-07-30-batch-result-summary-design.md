# 批量分析结果摘要设计

## 背景

运营同学批量上传海外电商平台客服会话后，目前页面只显示“已生成分析”的总数和逐条记录列表。列表能逐条复核，但缺少一个本批次的快速概览，用户需要人工扫过每条记录才能判断这批问题主要集中在哪些类型、责任方和证据强度上。

本次功能目标是在批量分析成功后，立刻展示“本批次结果摘要”，帮助运营先看整体趋势，再进入逐条复核。

## 目标

1. 在批量分析结果区域增加本批次摘要，位于批次标题下方、记录列表上方。
2. 摘要只统计本次批量上传成功生成的记录，不影响全局记录概览。
3. 展示本批次记录数、待复核数、问题类型分布、责任方分布和证据强度分布。
4. 复用现有前端标签映射，让摘要中仍显示中文业务标签。
5. 不新增模型请求、不新增后端接口、不改变批量分析 API 响应结构。

## 非目标

1. 不做逐条失败统计。本轮沿用当前后端行为：批量分析要么整体成功返回记录，要么整体失败并显示错误。
2. 不把批次摘要中的分布项做成筛选按钮，避免和全局记录筛选混淆。
3. 不修改持久化结构，不新增数据库字段。
4. 不扩展为跨批次趋势分析。

## 推荐方案

采用前端本批次摘要方案。`POST /api/analyze-batch-file` 成功后，前端已经拿到 `payload.records`，可以直接从这些记录中计算当前批次摘要：

- `total_records`：使用 `payload.count` 或 `payload.records.length`。
- `unreviewed_records`：批量新生成记录默认尚未复核，因此等于当前批次记录数。
- `issue_categories`：统计 `record.analysis.attribution.issue_category`。
- `responsibilities`：统计 `record.analysis.attribution.primary_responsibility`。
- `evidence_strengths`：统计 `record.analysis.attribution.evidence_strength`。

统计函数放在 `src/customer_issue_agent/static/app.js`，作为纯前端 helper，例如 `buildBatchSummary(records)` 和 `rankBatchSummary(counter)`。渲染函数使用独立的 `renderBatchSummary(payload)` 或 `batchSummaryHtml(summary)`，由 `renderBatchResults(payload)` 组装到批量结果区域。

## UI 与交互

批量分析成功后，结果区域结构调整为：

1. 顶部继续显示“批量分析完成”、记录数量和批次号。
2. 中间新增“本批次摘要”卡片区。
3. 下方继续显示逐条分析记录和复核表单。

摘要卡片建议包含：

- 指标卡：`本批次记录`、`待复核`。
- 分布卡：`问题类型`、`责任方`、`证据强度`。

分布行展示中文标签和数量。若某个维度没有值，使用现有 `labelFor()` 的兜底规则显示“未知”。批次摘要中的分布行只展示文本，不触发平台或全局筛选。

## 数据流

1. 用户上传批量文件。
2. 前端提交到 `/api/analyze-batch-file`。
3. 后端完成批量分析并返回 `{ batch_id, count, records }`。
4. 前端 `renderBatchResults(payload)` 调用批次摘要 helper。
5. 前端先渲染摘要，再渲染逐条记录卡片。
6. 每条记录仍通过已有反馈表单进入复核流程。

## 错误处理

本轮不改变后端错误模型：

- 文件缺失、格式无法解析或整体分析失败时，继续显示现有批量错误提示。
- 只有接口成功返回 `records` 时才渲染本批次摘要。
- 如果 `records` 为空或字段缺失，摘要应安全渲染为 0 或“暂无数据”，不能让页面脚本报错。

## 测试策略

采用现有轻量前端 hook 测试方式：

1. 更新 `tests/test_app.py` 中静态 JS hook 测试，确认脚本包含批次摘要相关函数名，例如 `buildBatchSummary` 和 `renderBatchSummary`。
2. 增加或扩展测试，确认批量结果渲染路径包含“本批次摘要”“待复核”等文案。
3. 保留现有批量接口测试，确保 API 响应结构不变。
4. 运行完整测试套件，确认现有记录概览、筛选、导出和复核流程没有回归。

## 验收标准

1. 批量分析成功后，页面在记录列表上方显示本批次摘要。
2. 摘要数量与当前批次返回记录一致。
3. 问题类型、责任方和证据强度按数量降序展示。
4. 批次摘要不影响全局记录概览和本地筛选状态。
5. 批量失败时仍显示现有错误提示，不显示过期摘要。
6. 测试通过，且未新增后端 API 或模型请求。

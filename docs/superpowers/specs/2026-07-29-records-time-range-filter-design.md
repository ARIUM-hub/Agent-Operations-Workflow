# 记录时间范围筛选设计

## 背景

客户使用问题归因智能体已经支持分析记录保存、人工复核、全量和筛选 CSV 导出、最近记录筛选以及运营概览。当前运营概览和 CSV 导出默认都基于全部本地 JSONL 记录，适合全量复盘，但不方便回答“最近一周是否集中出现某类问题”或“最近 30 天修正比例如何”这类周期性运营问题。

本轮目标是在不引入数据库、复杂日期选择器或图表库的前提下，为运营概览和 CSV 导出增加轻量时间范围筛选。

## 目标

- 支持按记录 `created_at` 过滤分析记录。
- 支持时间范围：`all`、`7d`、`30d`。
- `all` 为默认值，保持现有行为不变。
- `/api/records/summary?range=7d` 只汇总最近 7 天记录。
- `/api/records/export.csv?range=30d` 只导出最近 30 天记录，并可与现有筛选条件叠加。
- 前端运营概览增加时间范围下拉，切换后重新加载概览。
- 前端“导出筛选 CSV”带上当前时间范围。

## 非目标

- 不做自定义起止日期。
- 不做趋势折线图、柱状图或同比环比。
- 不做时区配置 UI。
- 不引入数据库索引或后台异步报表。
- 不改变 JSONL 原始记录。
- 不调用模型，不增加供应商请求。

## 推荐方案

扩展现有 `record_filters.filter_records()`，新增 `range` 参数。它继续负责所有记录过滤，包括平台、问题类型、责任方、复核状态、关键词和时间范围。这样 CSV 导出和运营概览可以复用同一套筛选规则。

时间判断基于记录的 `created_at` ISO 时间字符串。实现时使用 Python 标准库解析时间，并以当前 UTC 时间作为基准：

- `all`：不过滤时间。
- `7d`：保留 `created_at >= now - 7 days` 的记录。
- `30d`：保留 `created_at >= now - 30 days` 的记录。

为保证测试稳定，内部可提供 `now` 参数给单元测试注入固定时间；FastAPI 端点不暴露该参数。

## 备选方案

方案 A：在 summary 模块单独做时间过滤，CSV 导出继续使用原筛选模块。实现局部简单，但会产生两套过滤逻辑，后续维护容易漂移，因此不采用。

方案 B：前端只筛选概览，导出不支持时间范围。对用户来说容易困惑，因为概览和导出的统计口径不一致，因此不采用。

方案 C：直接做自定义日期范围。能力更强，但需要日期控件、日期解析错误提示和更多边界测试，不适合当前 MVP 小步迭代。

## API 设计

### 运营概览

`GET /api/records/summary?range=7d`

可选参数：

- `range=all`：全部记录，默认。
- `range=7d`：最近 7 天记录。
- `range=30d`：最近 30 天记录。

未知 `range` 按 `all` 处理，避免用户手写 URL 时导致页面报错。

### CSV 导出

`GET /api/records/export.csv?range=30d&feedback_status=corrected&q=安装`

`range` 可与现有参数叠加：

- `platform`
- `issue_category`
- `responsibility`
- `feedback_status`
- `q`

多个条件继续使用 AND 逻辑。无匹配记录时仍导出只有表头的 CSV。

## 前端设计

在“运营概览”标题区域增加时间范围下拉：

- 全部记录
- 最近 7 天
- 最近 30 天

页面加载时默认选择“全部记录”并加载 `/api/records/summary?range=all`。用户切换范围后，前端重新调用 summary API 并刷新概览卡片。

“导出筛选 CSV”按钮读取同一个时间范围下拉，把 `range` 参数加入导出 URL。这样用户看到的概览时间范围和导出的时间范围默认一致。

## 错误处理

- `created_at` 缺失或无法解析：在 `7d`/`30d` 范围下不匹配；在 `all` 范围下保留。
- 未来时间记录：如果在范围起点之后，则保留。这样不会因为本机时间轻微漂移丢记录。
- 未知 `range`：按 `all` 处理。
- 前端 summary 请求失败：保留现有中文错误提示，不影响分析和导出。

## 测试策略

- 单元测试覆盖 `filter_records(range=...)`：`all`、`7d`、`30d`、未知范围、缺失或非法 `created_at`。
- API 测试覆盖 summary 的 `range` 参数。
- API 测试覆盖 CSV 导出的 `range` 参数与已有筛选条件叠加。
- 页面测试覆盖时间范围下拉和 JS 钩子。
- 回归测试确认不带 `range` 时 summary 和 CSV 导出行为不变。

## 验收标准

- 用户可以在运营概览切换全部、最近 7 天、最近 30 天。
- 概览统计会按所选时间范围变化。
- `导出筛选 CSV` 会带上当前时间范围，并按全部本地 JSONL 记录过滤导出。
- 不带 `range` 参数时保持现有全量行为。
- 全量测试通过。
